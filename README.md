# 南京大学计算机国际会议报销工作流

面向南京大学参加计算机领域国际会议的同学，帮助你从出访前的 OA 申请开始，逐步完成行程与预算准备、审批跟进、票据收集、汇总表填写和 PDF 提交前检查，尽量减少补件与返工。

**不用等材料齐了才开始，也不用先学会写代码。** 还没填 OA 也可以开始。告诉 Agent 你参加什么会议、当前办理阶段、目前有什么材料，它会先检查已有内容，再帮助查找或获取缺少的材料。Agent 指你使用的、能够阅读文件并协助处理任务的 AI 助手。

本项目是辅助整理工具，不是学校发布的报销规定。以下办事说明主要面向学生出国（境）参会；境内会议、教职工、团组和专项资助应先核对各自流程。具体材料、费用范围及审批要求，以学校现行规定和经办部门要求为准。本仓库不包含任何同学的真实报销材料或个人信息。

## 项目组织：用规则共同优化财务流程

项目由一条条有依据、可检查的规则组成。**新需求补充场景规则 → Agent 整理材料并生成 PDF → 逐条检查、修正和复查 → 全部适用规则通过 → 形成交给经办老师、财务老师的最终 PDF。** 执行顺序和交付条件统一维护在[工作流程](skills/reimbursement-workflow/references/workflow.md)，README 作为使用入口。

| 位置 | 用途 |
| --- | --- |
| [规则索引](skills/reimbursement-workflow/references/rules.md) | 通用规则、场景范围和状态 |
| [场景目录及模板](skills/reimbursement-workflow/references/scenarios/SCENARIO_TEMPLATE.md) | 新需求、限定条件、正反例和替代关系 |
| [维护指南](CONTRIBUTING.md) | 怎样新增、修改和共同维护规则 |
| [财务复核说明](skills/reimbursement-workflow/references/finance-review.md) | 对照实际最终 PDF 逐条检查与修正 |
| [复核记录模板](skills/reimbursement-workflow/assets/review.md) | 规则结果、对应页码、原件和剩余问题；填写后存入私人材料目录 |

有新需求时，先查已有场景；能覆盖的补充原规则，不能覆盖的新增场景，再登记到规则索引。写清适用条件、依据、边界和替代范围；没有依据的条目标为待确认。规则和维护说明使用中文，文件名、命令和标识符保留英文。

“通过全部规则”指所有适用条目都有依据地通过，不适用条目有明确理由，且没有影响交付的未通过或待确认事项。Agent 应检查实际 PDF 的内容和页面效果，修正后复查；脚本成功、文件存在或哈希一致不能代替内容检查。最终文件及规则版本、文件哈希和检查结果应可追溯。所需纸质原件和签章仍按规则核对，并记录随附方式。Agent 判断材料可交付，不等于财务已经审批通过。

## 1. 怎么开始

先下载并解压仓库，或使用 Git 克隆。为自己的材料另建一个私人文件夹，不要把护照、发票和付款记录放进这个代码仓库。

### 方式一：上传一个文件就开始

适合可以上传附件的聊天工具。

1. 下载仓库中的 [START_CHAT.txt](START_CHAT.txt)，上传到聊天中；不能上传文本文件时，也可以粘贴其完整内容。
2. 再提供你手头已有的材料，不齐也可以。
3. 发送下面这段话，填上已知信息，其他写“不清楚”：

```text
请按附件里的工作流，用中文协助我整理南京大学计算机国际会议报销材料。

我的院系和学生身份：……
当前阶段：还未填 OA／审批中／已获批待出行／已回国／已提交报销
会议名称、地点和出行日期：……
经费来源或项目：……（不清楚可以先留空）
我已有的材料：……
纸质原件目前在哪里、哪些已交：……

请先检查已有材料，查适用规定，从我的当前阶段继续。
还没填 OA 时，先帮我整理申请字段、拟定行程、预算和附件，
有已授权的浏览器工具时协助填写；提交前让我核对具体内容。
没有网站操作能力时，提供可逐项粘贴的草稿。
需要我登录、签字、盖章或领取原件时，说明具体要做什么。
请单独提醒需要原件的项目，以及旅行社机票发票。
最后整理汇总表、合集 PDF、复核结果和仍需办理的事项。
如果当前工具不能完成某一步，请明确说明，并先继续能做的部分。
```

`START_CHAT.txt` 已包含流程、参考说明和记录模板，不必逐个上传引用文件。文件包含中文规则和既有英文执行参考，你可以直接要求 Agent 用中文沟通。使用现成文件不需要安装 Python。

### 方式二：让 Agent 直接读本地文件

适合能够访问本地文件的 Codex 或其他 Agent。不安装 Skill 也可以开始。

在 Agent 中打开你的私人材料文件夹，然后发送：

```text
请读取 [工作流文件夹的完整路径]/skills/reimbursement-workflow/SKILL.md，
按照其中的流程，用中文协助我整理南京大学计算机国际会议报销材料。

我的材料目录是：[私人材料文件夹的完整路径]。
我的院系、身份、会议和出行情况是：……
当前阶段是：……；还未申请时请从 OA 草稿、预算和附件开始。
先检查已有材料，保留我的最新修改，再列出并推进缺少的事项。
请把工作记录和生成文件保存在我的私人材料目录中。
```

把方括号替换成实际路径。如果 Agent 无法读取某个目录，通过所用工具的文件访问设置提供访问权限，或改用方式一。

### 方式三：在 Codex 中安装 Skill，方便以后复用

把本仓库的整个 `skills/reimbursement-workflow` 文件夹复制到私人材料目录下的 `.agents/skills/` 中。不要只复制 `SKILL.md`，也不要覆盖已有安装。


在 Codex 中打开 `my-private-case`，发送：

```text
请使用 $reimbursement-workflow，用中文整理当前目录中的
南京大学计算机国际会议申请及报销材料。

```

如果没有识别到 Skill，先检查目录层级，再重启 Codex；也可按方式二直接指定 `SKILL.md`。安装与发现机制见 [OpenAI 官方 Skill 说明](https://learn.chatgpt.com/docs/build-skills)。

### 从 OA 填写开始

学校要求因公出访前完成审批并取得任务批件；学生、教职工和团组的入口不同。学生先按现行指南核对“学生出国（境）审批”入口，Agent 再根据实际页面逐项协助，不能拿别人的申请表当成当前系统字段。见[学校办事指南](https://wb.nju.edu.cn/splc/list.htm)。

1. **读已有材料**：会议官网或邀请函、拟出行日期和路线、经费来源，以及当前 OA 页面或字段。没有的信息逐项问，不要求出发前就提供回国票据。
2. **准备可核对的草稿**：按页面字段整理申请内容、会议与出行日期、完整行程、预算估算及附件清单。报价注明来源、日期和币种，未确认的经费留待确认；预算不当成实际报销金额。
3. **协助填写**：你完成正常登录与身份验证后，Agent 在工具和授权允许时填写、上传；没有网站操作能力时，给出可粘贴内容，并检查你提供的页面文字或截图。
4. **核对并跟进**：提交前检查完整草稿、预算和附件，学生 OA 由申请人本人点击提交，Agent 可以协助填写和上传。记录提交回执及审批结果；退回则按意见修改，获批后核对批件并提醒获取所需原件。
5. **接着整理报销**：保留拟定、获批、实际行程的区别，旅途中提醒留存票据，回国后接续核销与报销。已获批的申请不重复创建；行程变更先核对变更手续。

草稿使用 [OA 申请记录模板](skills/reimbursement-workflow/assets/oa-draft.md)，保存在你的私人材料目录。**“已填好”“已提交”和“审批通过”分别记录**，不互相替代。已出行但未确认行前审批的，应向经办部门确认处理办法，不倒填审批记录。

## 2. 第一次需要提供什么

先提供这些信息即可，不需要预先填写所有表格：

| 信息 | 说明 |
| --- | --- |
| 院系、学生身份 | 例如本科生、硕士生、博士生，用于判断适用流程 |
| 会议和行程 | 会议名称、官网或邀请函、国家或地区、城市、出发和返回日期 |
| 经费来源 | 已知的项目、资助计划或经费承担方；不清楚就注明待确认 |
| 已有文件 | 发票、收据、订单、付款记录、审批材料、最新版汇总表等，有多少先给多少 |
| 当前办理进度 | 还未填 OA、审批中、已获批、旅行中或回国后；如已交材料，说明实际交付版本及签章、核销情况 |
| 行前申请材料（如适用） | 邀请函或会议说明、拟定行程、报价或预算依据、经费信息、当前 OA 字段或页面；没有的先标出 |
| 原件情况 | 哪些是纸质原件，谁保管，是否已经交给经办老师 |

如果你已经修改过 Word，请提供最新保存版本；不希望改动的已提交材料，要明确说明。已确认备好的纸质材料可以单独交付，不必为消除“缺文件”提示而重复上传。

## 3. 通常要整理哪些材料

下表是材料收集入口，**不是要求每个人无条件准备全部项目**。只整理与你实际行程、费用和经费要求有关的材料；Agent 应区分“已经有”“需要补”“不适用”。学校公开核销材料清单包括任务批件、汇总表、OA 校内审批表、邀请函、证件及出入境记录复印件、相关票据，见[外汇核销办理须知第 4 项](https://wb.nju.edu.cn/60/db/c4136a155867/page.htm)。

| 类别 | 建议先交给 Agent 检查的材料 | 重点提醒 |
| --- | --- | --- |
| 出访审批 | 正式任务批件、OA 导出的校内审批表 | **正式批件与 OA 审批截图不是同一种材料**；原件另见下节 |
| 会议材料 | 邀请函、会议名称和日期、已有注册确认 | 费用项目和参会行程应能对应 |
| 汇总表 | 学校原始模板、你最新填写的 Word | 没有模板时，由 Agent 帮忙找；保留原模板和你的确认内容 |
| 证件与行程 | 护照信息页、签证或签注、出入境记录等适用页面 | 与审批、机票和实际行程交叉核对；不把证件原件默认作为归档附件交走 |
| 机票 | 发票或适用的报销凭证、行程资料、订单、付款记录 | **旅行社订票时，明确索取旅行社机票发票**；不能只给预订确认 |
| 火车及其他交通 | 票据、日期、起讫地点、需要时的付款证明 | 有票据不代表费用一定可报，先核对范围 |
| 住宿 | 酒店账单或发票、住宿明细、付款记录 | 核对入住日期、晚数、人数、金额；例外情形另备证明 |
| 会议注册费 | 发票或收据、订单和付款记录；需要时补收费标准 | 将同一笔费用的多个证明关联起来，不重复计费 |
| 签证及保险 | 签证费收据、相关服务费发票、保险凭证和付款记录 | **纸质签证收据原件单独保管、提醒携带** |
| 补助及说明 | 与实际申请对应的说明和签章材料 | 申请学生补助时再核对相应要求，不默认每个人都申请 |

学生申请出国补助时，学校另有书面说明、经费信息及签章要求，见[核销须知第 5 项](https://wb.nju.edu.cn/60/db/c4136a155867/page.htm)。外文票据需要中文说明并由经办人签字，见[第 14 项](https://wb.nju.edu.cn/60/db/c4136a155867/page.htm)。具体填写内容由 Agent 对照原文检查。

### 旅行社订机票：一定单独核对发票

请明确告诉 Agent 机票是旅行社订的。它应优先查找已授权邮箱或本地文件中的旅行社机票发票；尚未开具时，帮助整理索票所需的抬头和订单信息。

- 需要单位抬头的国内发票，抬头按要求填写 **南京大学**，其余开票信息使用学校提供的准确资料；不要把这一要求机械套到境外外文票据。
- 核对发票金额与订单、付款及申报费用，不能把同一笔机票费算两次。
- 行程资料、报价单、预订确认和付款截图，各有用途，不能直接当作旅行社发票。
- 如学校认可其他正式报销凭证，应记录适用依据，避免要求重复开票。
- 原生电子发票保留原文件；需要怎样提交或打印，按经办要求执行，不凭空增加“纸质原件”要求。

## 4. 哪些材料要特别提醒原件

> **合集 PDF 齐全，不等于纸质原件已经备好或交到。**
>
> 本流程重点提醒 **OA 正式任务批件原件** 和 **纸质签证费收据原件**。这是材料准备提示；公开须知未逐项说明的原件形式和收取方式，应向经办部门确认，不能扩展成“所有电子票据都要纸质原件”。

| 材料 | 怎样准备 | 不要混淆 |
| --- | --- | --- |
| **OA 正式任务批件原件** | 保留、携带学校正式出具的盖章批件，按认可渠道领取或打印，并记录交付情况 | OA“审批通过”的页面、导出预览或自行打印的截图，不能自动视为所需正式原件 |
| **纸质签证费收据原件** | 收到时即妥善保管；扫描件用于整理，纸质原件列入携带和提交提醒 | 扫描件清晰，也不代表它能替代要求提交的纸质原件 |
| **需要签字盖章的表格或说明** | 按适用要求取得完整签章版本，确认交纸质还是通过指定系统提交 | 无签章的 Word/PDF 不能证明签章已经办完 |
| **旅行社等开具的电子发票** | 保存原始电子文件，并核对提交要求 | 电子原文件与扫描纸票不同，不自行要求不存在的纸质原件 |
| **其他纸质票据** | 先保留原件，再逐项确认是否需要提交 | 不因已放入 PDF 就丢弃原件，也不假定所有票种规则相同 |

学校说明任务批件可在线生成、经校园自助打印机打印，见[师生出国境系统通知](https://itsc.nju.edu.cn/53/07/c21558a611079/pagem.htm)。该 2023 年通知在此仅用于说明批件获取方式；学生核算顺序以现行学生办事指南为准。实际领取或打印方式按当前 OA 指引办理，这不等同于用普通打印机打印任意审批页面。

提交前，让 Agent 单独给出一张**原件携带清单**，不要把提醒藏在几十页 PDF 中：

| 材料 | 状态 | 保管或交付信息 |
| --- | --- | --- |
| OA 正式任务批件原件 | 待获取／已备好待携带／已交 | 由你补充 |
| 纸质签证费收据原件（如适用） | 待获取／已备好待携带／已交 | 由你补充 |
| 其他按要求提交的原件 | 逐项填写 | 由你补充 |

确认“已备好”的材料应提醒携带，不应反复报成缺件；确认“已交”的要记下交给谁、何时交。原件找不到时，先向经办老师确认可接受的补办凭证，再联系出具方，不能自行认定复印件足够。

## 5. Agent 会做什么，还需要我做什么

![南京大学计算机国际会议报销流程图：OA 申请、行前审批、材料收集、费用核对、文档制作、提交复核，以及旅行社发票和纸质原件提醒](docs/assets/reimbursement-workflow.png)

蓝绿色部分是 Agent 协助处理的工作，橙色部分提示人工配合及原件事项；遇到缺件或错误，返回对应步骤补齐并重新检查。

Agent 在已有工具和授权范围内，可以查规定、整理 OA 字段与预算、协助填写及跟进申请、下载模板、取发票、整理台账、填表、导出和检查文件。登录验证、签字、盖章、领取与交付原件，以及经办部门的核算和审核，仍需本人或相关老师完成。学校目前公布的学生出国（境）报销顺序是：**自行填写汇总表 → 国际化处线下外汇核算 → 财务处报销**；院系办理和签章环节也要按适用要求完成，不能用“已生成 PDF”代替。见[办事指南“个人出访—总结报销”](https://wb.nju.edu.cn/splc/list.htm)。

工具不全时也能开始：没有邮箱连接就先整理本地文件；无法登录网站时由你完成登录或导出；没有 Word/PDF 编辑或渲染能力时先做材料核对，明确标记尚未完成的文档步骤。不要向聊天中粘贴密码或验证码。

## 6. 最后应拿到什么

- **OA 申请草稿与进度记录（从行前开始时）**：字段及来源、拟定行程、估算预算、附件、提交回执和审批结果；已完成的申请直接沿用。
- **材料与费用记录**：每项要求对应哪些证据，哪些费用计入，哪些问题仍待确认。
- **可编辑的汇总表 Word**：沿用学校模板，保留已确认内容和应由经办部门填写的空白。
- **检查过的汇总表 PDF 和合集 PDF**：版本一致、页面清楚、顺序可追溯；以工具实际完成的结果为准。
- **原件携带清单和剩余待办**：明确你接下来做什么、找谁确认、完成后怎样继续。
- **复核结果**：区分准备中、待复核、可提交，以及实际提交后的财务反馈。

如果核销、原件或签章尚未完成，交付物应写清当前阶段。财务要求补件后，提供新的要求即可继续，Agent 应只更新受影响事项。只有取得实际审核反馈，才能记录通过；“已交材料”不等于“审核通过”。

## 8. 办理中容易踩的坑

下面是整理工作应吸取的经验，已落实到 Agent 的检查和记录中。它们不表示所有同学都遇到过财务退回，也不把某一次办理要求扩大成全校规定。

| 容易返工的地方 | 工作流怎样提前处理 |
| --- | --- |
| 扫描件齐了，却忘了带纸质原件 | 分别记录电子文件、所需原件、保管人及交付情况；出门前单独提醒 OA 正式任务批件、纸质签证收据等适用原件 |
| 旅行社发来行程资料，就以为机票材料齐了 | 单独核对机票发票、订单及所需付款证据；多人资料先查他人信息，必要时索取本人专用材料 |
| 改了新版 Word，合集仍放着旧表 | 以最新保存文件和确认内容为准，修改后重新导出、合并并检查；连目录、书签和页码对应也一起更新 |
| 原模板重填与局部排版修复混在一起 | 先识别这次要做哪一种；只修排版时保留当前合并单元格、文字和有意留空的字段 |
| 表格看着紧凑，却挤掉了签字位置 | 看实际导出的页面，特别检查底部、换行、左右对齐和上下签字区；不为了压成一页丢掉必要内容 |
| 一起打印，被误算成一起报销 | 每项材料注明属于哪笔报销或哪次单独交付；打印范围与费用小计、附件数分开。备选汇总表需明确最终选用哪版 |
| 自动补回被删掉的金额、项目或旧附件 | 保存最新决定及被替代的旧决定；空白不等于零，经办部门负责的核算字段不擅自填满 |
| 去了办公室，却不知道要办什么、带什么 | 给出一张交接清单：去哪个环节、带哪些文件和原件、哪些说明或签字还需手写、需要确认什么、回来提供什么结果 |
| 已交材料，被当成签章核销和财务审核都完成 | 分开记录材料交付、签章、核销和实际审核结果；本人专属的 OA 提交、老师负责的报销交接按具体流程执行 |
| 把 Agent 提醒的疑点写成财务已经退回 | 区分已发现问题、本人报告的缺件、待确认风险和实际退回原因；有新回复只更新受影响事项，不重复追问已确认的材料 |

给 Agent 补充办理结果时，一句话就可以，例如：“汇总表已签字，原件还在我这里，老师要求补一份本人订单。”它应接着处理对应事项，而不是要求重新介绍全部背景。手写中文说明和签字尚未完成时，要留在待办里；删除电脑生成的说明不代表这一步已经完成。

## 9. 想先试用或继续维护

不想先放入个人材料，可以使用[虚构示例](examples/synthetic/README.md)。这些文本展示费用去重、币种分开、日期差异和纸质材料记录，不是真实票据，也不是一套已可提交的报销材料。

流程源文件统一维护在 [workflow.md](skills/reimbursement-workflow/references/workflow.md)。[启动提示](prompts/start.md)、[材料收集说明](skills/reimbursement-workflow/references/collection.md)、[财务复核说明](skills/reimbursement-workflow/references/finance-review.md)及[首次使用检查记录](evals/first-use.md)可供进一步查看。OA 环节已加入流程和情景检查清单，但尚未用真实账号验证完整的 OA 页面操作；实际字段、工具能力与审批结果须现场确认。新规则、维护指南和场景说明以中文维护；程序、命令和标识符保留英文，既有执行参考按需更新。规则的维护方式见 [CONTRIBUTING.md](CONTRIBUTING.md)。

维护者修改流程后，可在仓库根目录运行以下命令生成新的聊天版文件，检查后再替换仓库里的旧版：

```sh
python3 scripts/export_chat_bundle.py START_CHAT-new.txt
```

可选的 Python 3.10+ 文件校验工具只检查文件是否变化，**不能证明内容正确或财务会通过**。普通使用者无需运行它；需要时查看[工具说明](skills/reimbursement-workflow/references/integrity.md)。维护者可运行：

```sh
python3 -m unittest discover -s tests -v
```

请把真实材料保留在仓库外的私人目录，不要上传到提交历史、Issue 或示例中。提供问题反馈时，使用脱敏描述或虚构样例。项目采用 [MIT 许可证](LICENSE)。
